# Discrete-domain function dataset

Records of the form **(observed examples, function definition)**: a list of `(x, y)`
pairs produced by one hidden rule, paired with that rule's structured identity and its
English description. It is the supervision needed to learn — or to score — a map from
observed behaviour to a description of it.

Generated by [`scripts/generate_dataset/discrete.py`](../../scripts/generate_dataset/discrete.py)
from the families in [`src/datasets/discrete.py`](../../src/datasets/discrete.py). The
continuous-domain counterpart is [`src/datasets/continuous.py`](../../src/datasets/continuous.py).

## Files

| file | contents |
|---|---|
| `discrete_functions.jsonl.gz` | The dataset: gzipped newline-delimited JSON, one record per line. |
| `discrete_functions.summary.json` | Generation arguments and the resulting counts. |

Regenerate with (output is byte-identical to the committed file):

```bash
python scripts/generate_dataset/discrete.py --out data/discrete/discrete_functions.jsonl.gz
```

Load with:

```python
from src.datasets.discrete import load_dataset, format_examples

records = load_dataset("data/discrete/discrete_functions.jsonl.gz")
print(format_examples(records[0]["examples"]))   # "x = -8 -> f = 0" per line
print(records[0]["description"])
```

## Scale

15,336 records over 1,278 distinct rules, 0.7 MB compressed.

| split | records | meaning |
|---|---|---|
| `train` | 9,084 | Most parameter values of the training families. |
| `heldout_param` | 3,024 | Parameter values of training families, interleaved with the training values rather than taken from one end. |
| `heldout_composition` | 2,940 | `gt_and_mod` — a composition of two concepts each seen separately in training. |
| `heldout_family` | 288 | `absgt` — a family never seen in training. |

Every record of a given rule sits in one split, and `train` and `heldout_param` share no
parameter setting within a family.

Families: `gt`, `lt`, `absgt`, `range`, `mod`, `piecewise`, `lt_and_mod`, `gt_and_mod`
over integers in `[-30, 30]`; `bit_is_1`, `at_least`, `bits_equal` over 6-bit strings.
The bit families are small by construction — a 6-bit domain admits only 6 single-bit
rules and 15 bit-pair rules — so family counts are deliberately uneven.

## Record schema

```json
{
  "function_id": "range_a=-30_b=-22",
  "family": "range",
  "params": {"a": -30, "b": -22},
  "domain": "int",
  "split": "train",
  "labels": ["0", "1"],
  "description": "Output 1 if x is strictly between -30 and -22, otherwise output 0.",
  "paraphrases": ["Output 1 if x is strictly ...", "Return 1 when -30 < x < -22, ...", "..."],
  "expression": "1 if -30 < x < -22 else 0",
  "domain_size": 61,
  "label_counts": {"0": 54, "1": 7},
  "majority_label_fraction": 0.885246,
  "n_examples": 8,
  "view": 0,
  "examples": [[-8, "0"], [-24, "1"], [-13, "0"], "..."],
  "holdout_examples": [[3, "0"], [-22, "0"], "..."]
}
```

- **`description` / `paraphrases`** — the target of verbalization. `paraphrases[0]` is
  the canonical description and equals `description`; the alternatives say the same
  thing in different words, so a method is not rewarded for matching one surface form.
- **`expression`** — the same rule in Python syntax, for reconstructing it
  programmatically instead of parsing prose. Labels are strings, including `"0"`/`"1"`.
- **`params`** — the structured identity. Scoring a generated description against
  `family` and `params` is more informative than string comparison, and separates the
  two failure modes worth distinguishing: naming the wrong *kind* of rule, and naming
  the right kind with the wrong *numbers*.
- **`majority_label_fraction`** — accuracy of the best constant predictor on the full
  domain. **Report fidelity against this baseline, not against zero.** It averages
  0.705 here, so a method scoring 0.70 has demonstrated nothing.
- **`view`** — index of the draw. Each rule appears `views` times per example-set size,
  with different observed inputs but the same rule, which is what distinguishes learning
  a rule from memorising one presentation of it.

## Design decisions worth knowing

**Held-out inputs are reserved per rule, not per record.** `holdout_examples` is fixed
for a rule and shared by all of its views, so different draws of the same rule cannot
leak each other's evaluation inputs. The reservation is allocated across labels *in
proportion to label frequency* (at least 2 per label, never more than half of a label).
A label-*balanced* reservation is the tempting alternative and is wrong on these small
domains: it takes nearly every instance of a rare label, leaving the observed examples
unable to show where the rule's boundary lies.

**Near-constant rules are dropped.** A rule is excluded when any label occurs fewer than
4 times over the domain, or when a constant predictor reproduces it more than 90% of the
time. Such rules are already solved by the constant baseline, so they inflate scores
without testing anything. The ceiling is a compromise: tightening it to 0.85 would cut
the `at_least` family from 4 usable rules to 2.

**Example sets are minority-enriched at small sizes.** Every example set is guaranteed
to contain at least 2 instances of each label, with the remainder drawn uniformly.
Without that guarantee a skewed rule sometimes yields an example set showing a single
label, which no method could describe. The cost is that at `n_examples = 8` the observed
label proportions are noticeably flatter than the rule's true proportions; at 32 the
distortion is small. If you need faithful proportions, regenerate with
`--min-per-label 0`.

**Families are capped independently.** `range`, `piecewise` and the two compositions
have combinatorially large parameter grids and would otherwise swamp the rest; each
family is capped at 300 rules by taking an evenly spaced subset of its surviving grid,
which preserves the full parameter span rather than a prefix.

**Generation is deterministic.** Every draw is keyed to a hash of the rule's identity
plus its view and size, so the same arguments reproduce the same file exactly.

## Useful knobs

`--example-sizes 8,16,32` · `--views 4` · `--n-holdout 16` · `--min-per-label 2` ·
`--max-majority-fraction 0.90` · `--min-minority 4` · `--max-per-family 300` ·
`--int-low -30` · `--int-high 30` · `--n-bits 6` · `--range-stride 1` ·
`--composition-stride 2` · `--seed 0`. Run with `--help` for the full list.
